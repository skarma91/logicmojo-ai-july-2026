PretrainingThe whole job: predict the next token

An LLM is trained on one simple task at massive scale: given the tokens so far, predict the next one. Repeat over a huge amount of text, and grammar, facts, and patterns are absorbed as a side effect of getting good at it.

This is the honest answer to "how does it know things": it got very good at predicting the next token.

PretrainingTrained to predict, not to answer

A base LLM is not trained to answer questions. It is trained to continue text. Faced with a question, it may just continue the pattern, for example writing more questions.

Answering is added laterThis next-token pretraining is only the first stage. Two more training stages, on the next slide, turn a base model into a helpful assistant.

ScaleMore scale, qualitatively new abilities

More data, parameters, and compute do not just nudge accuracy. Past certain thresholds, qualitatively new abilities appear, sometimes jumping from near-random to reliable.

  • Instruction following: small models ignore the ask; large ones follow it.
  • Few-shot learning: give two or three examples in the prompt and the model generalizes.
  • Basic reasoning: multi-step problems become tractable at scale.
There is no magic numberThe threshold is not a proven constant. It differs by task, and how sharp it looks depends on how you score: some jumps soften into gradual gains under a smoother metric. Read it as "roughly this scale", not an exact line.

ScaleIs bigger always better?

More scale helps in a predictable way (scaling laws), but "bigger" is not the whole story, and not always the right choice.

  • Data and compute, not just size: a smaller model trained on more, cleaner data can beat a larger, undertrained one (the Chinchilla result).
  • Small models are strong: models like Phi, Gemma, and Llama 3 8B, trained on high-quality data, match older much larger models on many tasks, and run cheaply.
  • Fit the task: a small, specialized model often beats a giant general one on a narrow job, at a fraction of the cost and latency.

Context windowThe working memory, in tokens

The context window is how many tokens the model can consider at once: its working memory. Everything must fit inside it, and it fills up fast.

Counted in tokensTie it back to class 3.1 (Text as data): the limit is measured in tokens, not words. A long document can eat the whole budget, which is why retrieval and memory become their own topics in Module 4 (LLMs and GenAI) and Module 5 (AI Agents).

Context windowIt does not remember past chats by default

The model only sees what is in the current context window. It keeps nothing between calls, so a chat app has to resend the whole history every turn.

Memory is engineeredAny sense of long-term memory is something we build: re-supplying past turns, or storing and retrieving them. That is a whole topic in Module 5 (AI Agents).

DecodingA probability for every next token

At each step the model outputs a probability for every possible next token. Decoding is how we pick one, append it, and run again. Generation is this loop.

The choice mattersAlways take the top token and the text is safe but repetitive. Sample from the distribution and it is varied but can wander. Temperature and top-p are the dials that balance the two.

DecodingTemperature: sharpen or flatten

The model gives each token a score (logit) \( z_i \). Softmax turns the scores into probabilities:

$$ p_i = \frac{e^{z_i}}{\sum_j e^{z_j}} $$

Temperature adds one knob: divide the scores by \( T \) before the softmax.

$$ p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}} $$

  • \( T < 1 \) sharpens: more focused, deterministic.
  • \( T > 1 \) flattens: more random, creative.
  • \( T \to 0 \) always takes the top token (greedy).

The nucleus, and the boundary tokenYou keep adding tokens until the total reaches or crosses \( p \), and the token that crosses it is included, then you stop. So the nucleus is the smallest set whose total is at least \( p \): here {mat, rug, sofa}, with the tail (floor, cliff) dropped.

DecodingTop-k, and combining the two

Top-k is the simpler sibling: keep the \( k \) most likely tokens, whatever their probabilities sum to. With \( k = 3 \), keep the top three and drop the rest.

Used together, not "either"They are two filters in a row, so a token must pass both. First keep the top-\( k \), then within those keep the top-\( p \) nucleus. The candidate set is the intersection: at most \( k \) tokens, and whichever filter is tighter wins.

DecodingTemperature 0 is not always best

It is tempting to set temperature to 0 for "correctness".

It is a dial, not a defaultTemperature 0 is best for exact tasks (extract a number, follow a strict format) and worst for creative ones (brainstorm, write a story), where it turns repetitive. Match the setting to the task.
