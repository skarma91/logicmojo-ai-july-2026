Multi-headRun attention several ways at once

One attention layer can only track one kind of relationship at a time. So we run several copies in parallel, called heads, each with its own learned Q, K, V projections. Each head is free to specialize.

  • One head might link a verb to its subject.
  • Another might link a pronoun to the noun it refers to.
  • Another might just track nearby words.
Then combineStack the heads' outputs side by side and pass them through one more linear layer that mixes them into a single result.

Multi-headMulti-head, by the dimensions

Heads do not add width. The model vector is split across heads, each head attends in its own smaller slice, then the pieces are concatenated and passed through one output projection \( W^O \) back to full width.

$$ \text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V) $$

$$ \text{MultiHead} = \text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W^O $$

Why splitEach head learns a different relationship inside its 64-dim slice. Concatenating recovers the full 512, and the output projection \( W^O \) mixes the heads back together. Head count grows with model size: 8 in the original transformer, 12 to 16 in BERT, and dozens (up to 96) in the largest LLMs.

PositionAttention is order-blind

Attention treats the sentence as a set. It scores every pair of tokens, but nothing in that score depends on where a token sits. Shuffle the words and the attention is identical.

The gapSo on its own, attention cannot tell "dog bites man" from "man bites dog". Word order carries meaning, and we have to add it back in.

PositionSinusoidal positional encoding

The original transformer adds a fixed position vector to each token embedding. Each dimension of that vector is a wave of a different frequency.

$$ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right) $$

  • \( pos \): the token's position (0, 1, 2, ...).
  • \( i \): the dimension index; even dims use \( \sin \), odd dims use \( \cos \).
  • Low dims are fast waves, high dims are slow waves, so every position gets a unique pattern.
  • Added to the token embedding: input = token_embedding + PE, so the same word in two places differs.

Position (RoPE 1 of 3)Rotate the vector by its position

Sinusoidal encoding adds a position vector. RoPE instead rotates each token's query and key by an angle set by its position: at position \( m \), spin the vector by \( m\theta \).

Spin a query \( q = (1, 0) \), with \( \theta = 30^\circ \) per position
  • pos 0: turn \( 0^\circ \rightarrow (1.00,\ 0.00) \)
  • pos 1: turn \( 30^\circ \rightarrow (0.87,\ 0.50) \)
  • pos 2: turn \( 60^\circ \rightarrow (0.50,\ 0.87) \)
  • pos 3: turn \( 90^\circ \rightarrow (0.00,\ 1.00) \)

Rotating \( (x,y) \) by \( \alpha \): \( (x\cos\alpha - y\sin\alpha,\ x\sin\alpha + y\cos\alpha) \).

Position (RoPE 2 of 3)Only the distance matters

Position (RoPE 3 of 3)Why RoPE wins

  • Relative by design: the score depends only on how far apart two tokens are, not where they sit, so the model gets relative position for free.
  • Long context: tokens at positions 5000 and 4997 are still "3 apart", so a model can run on sequences longer than it trained on.
The full versionA real vector is high-dimensional. RoPE splits it into pairs of dimensions and rotates each pair at its own rate, fast to slow, like the sinusoidal frequencies. Same idea, many dials at once.

PlumbingWhy deep stacks are hard to train

Backprop (class 2.3, Neural networks) sends the gradient back by the chain rule: at each layer it is multiplied by that layer's local slope. Those slopes are usually below 1, an activation's derivative times the weights, so the product shrinks fast.

If each layer's slope is about 0.6
  • after 3 layers: \( 0.6^3 \approx 0.22 \)
  • after 6 layers: \( 0.6^6 \approx 0.05 \)
  • after 12 layers: \( 0.6^{12} \approx 0.002 \)
The resultBy the early layers the gradient is almost zero, so they barely learn. Same vanishing gradient as class 2.3, now caused by depth.

PlumbingResidual connections fix it

A residual connection adds a layer's input back to its output.

$$ \text{output} = x + \text{layer}(x) $$

  • The gradient can flow straight back through the + x path, so it never fully vanishes.
  • Each layer only has to learn a small change to \( x \), not rebuild it from scratch.
  • This is what lets us stack dozens of blocks and still train them.

PlumbingLayerNorm, and why not BatchNorm

Why LayerNorm hereSequences vary in length, and at generation the batch is often a single token, so batch statistics are unreliable. LayerNorm works per token, independent of the batch, so it behaves the same in training and in one-token generation.

Feed-forwardThink per token, after attention

In the block the order is attention, then add and norm, then the feed-forward layer. So it never sees raw tokens: it receives each token's vector after attention has already mixed in context.

  • It is the small network from class 2.3 (Neural networks): Linear, ReLU, Linear.
  • The same network runs on every token independently, shared weights, no arrows between tokens.
What it buysAttention only re-weights and blends existing vectors. The feed-forward layer adds a non-linear transform per token, so the model can compute new features from the mixed context, not just average it. It holds much of the model's knowledge, often about two-thirds of the parameters.

The blockThe encoder block, assembled

Put the parts together and you get one block. Attention mixes across tokens, add and norm stabilize, the feed-forward layer thinks per token, add and norm again.

  • Every arrow is a residual-friendly step from the last few slides.
  • The shape in equals the shape out, so blocks can stack.
  • This is the encoder block: its attention is unmasked, so every token sees the whole sequence.

The blockThe decoder block adds two things

A decoder block is the encoder block with two changes, so it can generate text left to right.

  • Masked self-attention: the causal mask from class 3.2 (Attention), so a token sees only earlier tokens.
  • Cross-attention: an extra attention layer that looks at the encoder's output. Used only in encoder-decoder models (translation); decoder-only models like GPT skip it.
Decoder-onlyMost LLMs keep just the masked self-attention and the feed-forward layer, no cross-attention.

The stackRepeat the block N times

Stack the same block many times. Each one refines the representation a little more, and different depths learn different things.

  • Early blocks catch surface patterns: word forms, local phrases.
  • Middle blocks resolve grammar and references.
  • Late blocks capture meaning and long-range structure.
That is the whole modelA transformer is an embedding, a stack of N identical blocks, and an output head. Bigger models are mostly more blocks, wider vectors, and more data.

ArchitecturesEncoder-only: understand the whole text

A stack of encoder blocks with bidirectional attention: every token sees every other token, left and right, at once. It reads text into rich representations; it does not generate.

  • Models: BERT, RoBERTa, DistilBERT.
  • Where it shines: understanding tasks, classification, sentiment, named-entity recognition, embeddings and search.
A strength, not a limitThese are the jobs the architecture is best at because it sees the full input at once. Any transformer can be pushed at many tasks; this is where each design is natural.

ArchitecturesDecoder-only: generate the next token

A stack of decoder blocks with masked attention: each token sees only itself and the tokens before it. Predict the next token, append it, repeat. Almost every modern LLM is this.

  • Models: GPT, Llama, Mistral.
  • Where it shines: generation, chat, writing, code, and, through prompting, most tasks.
The one differenceThe causal mask is the whole change from an encoder. It is exactly what makes next-token prediction possible.

ArchitecturesEncoder-decoder: read one text, write another

An encoder reads the whole input into vectors; a decoder generates the output token by token, using cross-attention to look back at the encoder. This was the original transformer.

  • Models: T5, BART, Whisper, the original Transformer.
  • Where it shines: turning one sequence into another, translation, summarization, speech to text.

The outputFrom the last block to a next token

After the final block, one linear layer maps each token's vector to a score for every word in the vocabulary. Softmax turns those scores into a probability for the next token.

  • The output head is a matrix of shape \( d_{\text{model}} \) by vocabulary size.
  • Softmax over the vocabulary gives the next-token distribution.
  • How you pick from that distribution is decoding, the whole of class 3.5 (From models to LLMs).

BuildShapes at every stage

In the notebook you build one transformer block in PyTorch and pass a short sequence through it, printing the tensor shape after embeddings, after attention, after the feed-forward layer, and at the output. You apply a causal mask to make it a decoder block, and add an output head that turns the last vector into a next-token distribution. The architecture becomes concrete numbers, not a diagram.
